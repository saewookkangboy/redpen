# 3장 · 로컬 MCP · 읽기 도구 · 25분

## 이 장이 끝나면

- 내 노트북에서 도는 MCP 서버가 생긴다
- `/mcp` 에 `redpen-desk` 가 뜬다 ← **오늘 첫 번째 확실한 성과**

---

## 왜 도구를 따로 만드나

이 시스템은 신뢰등급을 계산합니다. 4점 이상이면 high, 2~3점이면 medium.

이 계산을 AI 에게 시키면 어떻게 될까요. **같은 답변에 매번 다른 등급이 나옵니다.**
그러면 문진 답을 하나 고쳤을 때 등급이 올라간 게 내 답변 때문인지 AI 기분 때문인지 알 수 없습니다.

> 같은 입력에 같은 답이 나와야 하는 것은 코드로 만듭니다.
> 기구 설계로 치면 검사 지그를 만드는 일입니다. 눈대중으로 재면 매번 다릅니다.

그리고 하나 더. 문진 답변에는 실명과 사내 정보가 섞입니다.
**이 도구가 내 노트북에서 돌기 때문에** 그 데이터가 밖으로 나가지 않습니다.

---

## 실습

Claude Code 에 붙여넣습니다.

```
mcp_server/server.py 에 FastMCP 기반 stdio MCP 서버를 만들어줘. 이름은 redpen-desk.
지금은 읽기 도구 2개만 만든다.

1) weight_rubric() -> str
   state/intake.json 을 읽어 체크리스트 항목별 점수와 신뢰등급을 규칙대로 계산한다.
   판단하지 않는다. 아래 규칙 그대로만 적용한다.

   - 문항3의 12개 보기 각각을 체크리스트 항목 R1~R12 에 매핑한다
     (매핑 표는 코드 상단에 CATALOG 라는 dict 로 두고, 항목마다
      id / 제목 / 자동판정 여부 / 대응 한 줄을 함께 적는다)
   - 빈도 점수: "4회 이상"=3, "2~3회"=2, "1회"=1, "기억 안 남"=0
   - 문항5(자유서술) 또는 문항6에 같은 취지의 내용이 있으면 +1
   - 문항7(통과 조건)과 반대 방향으로 일치하면 +1
   - 등급: 4점 이상 high / 2~3점 medium / 1점 low / 0점은 제외하되 unheard 에 남긴다
   - 문항9만 있고 문항3 선택이 없으면 점수 0으로 두고 unheard 에 넣는다

   반환: items[{id,title,score,confidence,judge,action,basis[]}], unheard[],
        answered, skipped[], high_count,
        improve_by(답하면 등급이 오를 가능성이 있는 문항 번호 배열),
        mode("review" 또는 "guide")
   문항 1이나 10이 비어 있으면 계산하지 말고 "필수 문항 누락" 을 반환한다.

2) score_draft(draft_path="drafts/sample-report.md") -> str
   마크다운 초안을 규칙 기반으로만 채점한다.
   - conclusion_in_first_10_lines: 첫 10줄에 숫자와 결론 키워드(결론|제안|권고|요청)가 있나
   - sourced_ratio: 숫자가 든 문장 중 앞뒤 한 줄 안에 출처 표기(출처|기준|집계|기간|월|분기)가 있는 비율
   - option_count: "대안 N" 또는 "안 N" 패턴 개수
   - hedge_count / hedge_lines: 미결 표현(검토 필요|추후|지속적으로|모니터링|향후|면밀히)
   - avg_para_chars: 문단 평균 글자 수
   반환: metrics + checks{R1,R2,R3,R4,R6,R11 각각 pass 와 위반 줄 번호}
   ★ 초안 본문은 반환하지 않는다. 지표와 줄 번호만 반환한다.
   파일이 없으면 {"mode":"guide"} 를 반환한다. 초안을 만들어내지 않는다.

프로젝트 루트에 .mcp.json 을 만들어 이 서버를 등록해줘.
mcp SDK 2.x 에서 FastMCP 가 MCPServer 로 이름이 바뀌었으니, 두 버전 모두에서 뜨도록
import 를 try/except 로 감싸줘.
마지막에 서버를 직접 실행해서 뜨는지 확인하고, 안 되면 고쳐줘.
```

## 생각해 볼 것

**왜 초안 본문을 반환하지 않고 줄 번호만 주나** (프롬프트의 ★ 줄)

문서 전체가 도구를 부를 때마다 대화에 들어가면 두 가지가 나빠집니다.
비용이 늘고, 에이전트가 원문 문체에 끌려갑니다.
**필요한 최소한만 넘기는 것** 이 하네스입니다.

**왜 도구를 2개로 끊었나**

도구가 많으면 에이전트가 뭘 부를지 헷갈립니다.
오늘 최종적으로 4개를 만듭니다. 읽기 2, 쓰기 2. 그 이상 늘리지 않습니다.
