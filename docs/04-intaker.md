# 4장 · 문진관 · 20분

## 이 장이 끝나면

- 첫 서브에이전트가 생긴다
- 내 기억이 **신뢰등급이 붙은 체크리스트** 가 된다

---

## 서브에이전트가 뭔가

`.claude/agents/` 에 마크다운 파일을 하나 두면 그게 위원 한 명입니다.
파일 맨 위 프론트매터에 이름, 언제 부를지, **어떤 도구를 쓸 수 있는지** 를 적습니다.

`tools:` 줄이 핵심입니다. 위원마다 권한이 다릅니다.
문진관은 계산 도구를 쓰고, 6장의 답변관은 아무 도구도 못 씁니다.

---

## 실습

```
.claude/agents/intaker.md 를 만들어줘.

프론트매터:
  name: intaker
  description: 문진 답변을 체크리스트로 구조화하고 신뢰등급을 붙인다. 가장 먼저 단독 실행한다.
  tools: Read, mcp__redpen-desk__weight_rubric

본문:
너는 문진관이다. 사람을 분석하지 않는다. 답변을 항목화한다.

절차:
1. weight_rubric 을 호출한다. 점수와 등급은 반환값을 그대로 쓴다. 직접 매기지 않는다.
2. 각 항목을 체크리스트로 쓴다. 항목마다 아래를 채운다.
   - 제목과 [신뢰등급 · 점수]
   - 근거: 문항 번호와 사용자의 실제 답변. 최소 1개
   - 대응: 문서를 어떻게 고치면 되는지. 한 줄
   - 판정: 자동 또는 수동
3. unheard 로 온 항목은 [회상 부족] 을 붙여 그대로 남긴다. 지우지 않는다.
4. improve_by 문항 번호와 그 문항의 질문 문구를 함께 알려준다.

출력은 마크다운. 프론트매터에 reviewer, source, answered, skipped, high_count, updated 를 넣는다.

금지:
- 답하지 않은 문항의 내용을 추측해 채우지 않는다
- 성격·성향·심리를 추정하지 않는다
  "꼼꼼한 편", "숫자에 민감", "완벽주의", "~한 스타일" 같은 표현을 쓰지 않는다
- 항목 수를 채우려고 억지 분류를 만들지 않는다. 3개면 3개로 보고한다
- 등급을 올려서 보고하지 않는다. low 는 low 로 보여준다
```

만들었으면 실행합니다.

```
intaker 서브에이전트를 실행해서 내 문진 결과로 체크리스트를 만들어줘.
아직 저장하지는 마.
```

## 화면을 보세요

이런 게 나옵니다.

```
## R1. 숫자에 출처·기간·집계 기준  [high · 5점]
- 근거: 문항3에서 «이 숫자 어디서 나왔어요?» 을 4회 이상 들음 (3점)
        문항5·6 답변에도 같은 내용이 있음 (+1)
        문항7 통과 이유에도 관련 내용이 있음 (+1)

## R6. 완료 시점  [low · 1점]
- 근거: 문항3에서 «언제까지예요?» 을 1회 들음 (1점)
- 우연일 수 있음
```

**여기서 잠깐 멈추세요.**

여러분 기억의 어떤 부분이 확실하고 어떤 부분이 흐릿한지가 지금 화면에 나와 있습니다.
high 는 여러 경로에서 같은 신호가 잡힌 것이고, low 는 한 번 들은 것입니다.

기억은 틀립니다. 그래서 이 시스템은 **기억을 사실처럼 다루지 않고 등급을 매깁니다.**

---

## 기억 — 하네스의 여섯 번째 요소

이 체크리스트는 `state/rubrics/{이니셜}.md` 로 저장됩니다.

다른 실습은 매번 새로 시작하지만, 이 시스템은 지난번에 배운 걸 파일로 들고 있습니다.
그리고 다음 장에서 보겠지만, **그 파일은 사람이 결재해야 저장됩니다.**

자동으로 쌓이는 기억과 사람이 승인한 기억은 다릅니다.

---

## 항목이 2개밖에 안 나왔다면

정상입니다. 문항3에서 두 개만 골랐거나 빈도를 낮게 답한 경우입니다.
지금 고칠 필요 없습니다. 8장에서 답을 바꿔 재실행하면 결과가 어떻게 달라지는지 봅니다.

**억지로 채우지 않는 것이 이 시스템의 규칙입니다.** 문진도 예외가 아닙니다.
