수강생용이 아닙니다. 배포 시 이 파일을 남겨도 되지만, 6절의 정답과 8절의 확장 계획은 미리 보여주지 마세요.

## 1. 3시간 타임라인 (180분)

| 시각 | 장 | 분 | 도달 상태 |
|---|---|---|---|
| 0:00 | 0 | 15 | 완성본 데모, 환경 초록, 선긋기 합의 |
| 0:15 | 1 | 20 | 문진 폼 완성, 내 답변이 `intake.json` 으로 |
| 0:35 | 2 | 20 | 규칙과 계약 |
| 0:55 | 3 | 25 | **`/mcp` 에 서버가 뜬다 — 첫 성과** |
| 1:20 | — | 10 | 휴식 |
| 1:30 | 4 | 20 | **내 기억이 등급 붙은 목록이 된다** |
| 1:50 | 5 | 20 | **승인 없이 저장하려다 막힌다** |
| 2:10 | 6 | 25 | **위원 셋이 동시에 돈다** |
| 2:35 | 7 | 20 | **준비 목록이 나온다** |
| 2:55 | 8 | 20 | 손 떼고 재실행, 회고 |
| 3:15 | | | 종료 |

180분을 넘습니다(195분). 실제 운영에서는 아래 중 하나로 흡수하세요.

- 휴식을 5분으로 (→190분)
- 0장 데모를 10분으로 (→185분)
- **8장을 15분으로 줄이고 검증 루프는 말로만** (→180분) ← 권장

**절대 줄이지 말 것: 1장(문진)과 7장(결과 화면).**
1장을 줄이면 재료가 남의 것이 되고, 7장을 줄이면 오늘의 결론이 안 나옵니다.

## 3. 배포 준비

### 태그 만들기

`main` 에 완성본이 있습니다. `scripts/build-tags.sh` 가 역으로 `step-0`~`step-7` 을 만듭니다.

```bash
./scripts/build-tags.sh
git push origin --tags
git push origin main
```

각 태그는 "그 장을 시작하는 상태" 입니다. `step-4` 는 3장까지 완료된 상태입니다.

### 수강생 공지 (1주일 전)

```
【안내】 준비물 없습니다. 노트북만 가져오세요.
수업 중에 12개 질문에 답하시면 됩니다. 기억나는 만큼만 답하셔도 됩니다.

미리 설치해 오시면 20분 아낍니다.
  https://github.com/<계정>/redpen 의 SETUP.md
설치가 안 되셔도 수업 초반에 같이 합니다.
```

### 당일 아침 확인

- `/hooks` 로 훅 이벤트명 확인. `SubagentStart`/`SubagentStop` 은 Claude Code 버전에 따라 달라집니다
- 강사 노트북에서 `./scripts/check.sh` 전체 초록 확인
- 프로젝터로 `web/index.html` 이 읽히는 글자 크기인지 확인 (1400px 기준)

## 4. 실패 지점과 대응

| 언제 | 무슨 일 | 대응 |
|---|---|---|
| 0장 | `uv` 가 PATH 에 없다 | 새 터미널을 열게 한다. 셸 재시작 안 하면 계속 안 됨 |
| 3장 | MCP 가 안 뜬다 | "MCP 연결이 안 된다, 서버를 직접 실행해서 오류를 보여줘" 를 그대로 입력시킴 |
| 3장 | `mcp.server.fastmcp` ModuleNotFoundError | SDK 2.x. `MCPServer` 로 바뀜. SETUP.md 에 대응 문구 있음 |
| 4장 | 체크리스트가 2개뿐 | **정상이라고 말한다.** 8장에서 답을 바꿔 재실행 |
| 4장 | 전 항목이 low | 문항3 빈도를 전부 "1회" 로 답한 경우. 그대로 두고 8장에서 다룸 |
| 5장 | 게이트가 안 걸린다 | `chmod +x .claude/gate.sh` |
| 5장 | AI 가 스스로 approvals 를 true 로 바꿈 | CLAUDE.md 의 "게이트 승인을 스스로 true 로 바꾸지 않는다" 확인 |
| 6장 | `trace.jsonl` 이 빈다 | `python3` 미설치 또는 `scripts/trace-log.sh` 실행 권한 없음. `chmod +x scripts/trace-log.sh` |
| 6장 | 답변관이 없는 숫자를 넣음 | `tools:` 에 검색이 붙었는지 확인 |
| 7장 | 빈 화면 | `file://` 로 열었음. `./scripts/serve.sh` |
| 전체 | 한 명이 크게 밀림 | `./scripts/reset.sh step-N`. **이유는 나중에 설명한다고 못 박고 시작하세요** |

**진도 편차 관리.** 30명 실습에서 한 명을 붙잡고 있으면 전체가 멈춥니다.
각 장 끝의 `check.sh` 가 그 역할을 대신합니다. 수강생이 스스로 초록을 확인하고 넘어가게 두세요.
장이 바뀔 때만 손 들라고 하고, 그 사이는 개입하지 마세요.

## 5. 소크라틱 질문 모음

각 장에서 답을 먼저 주지 말고 이걸 던지세요.

**3장**
- 신뢰등급을 왜 AI 가 아니라 함수가 정할까요? → 같은 답변에 같은 등급이 나와야 비교가 됩니다
- 왜 초안 본문을 반환하지 않고 줄 번호만 줄까요? → 비용, 그리고 원문 문체에 끌려가는 것
- 도구를 4개로 끊은 이유는? → 많으면 뭘 부를지 헷갈립니다

**5장**
- 부탁과 훅의 차이는? → 확률과 결정
- 왜 체크리스트에만 결재가 필요할까요? → 되돌리기 비용
- 금지 표현을 규칙과 도구에서 두 번 막는 이유는? → 정말 나가면 안 되는 건 두 겹으로

**6장**
- 왜 셋을 순서대로 안 돌릴까요? → 뒤 위원이 앞 위원 결론에 끌려갑니다
- 답변관에게 검색을 주면 어떻게 될까요? → `missing` 이 비고, 준비 목록이 사라집니다

**8장**
- HITL 과 HOTL 중 뭐가 어렵나요? → 정지 조건 설계
- 실명이 남으면 멈추라는 조건, 왜? → 무인이 되면 사람이 안 봅니다

## 6. 자주 나오는 수강생 질문

**"이거 상사 뒷조사 아닌가요?"**

0장에서 먼저 그은 선을 다시 짚으세요. 산출물이 사람 프로파일이 아니라 문서 체크리스트라는 것.
그리고 `save_rubric` 이 성격 추정 표현을 코드로 막는 걸 보여 주세요. 말보다 데모가 낫습니다.

**"기억으로 만든 건데 믿을 수 있나요?"**

믿으라고 만든 게 아닙니다. **등급을 매기라고 만든 겁니다.**
low 항목이 흐리게 보이는 게 이 시스템의 정직함입니다. 8장의 검증 루프로 연결하세요.

**"실제 코멘트를 모아 오면 더 정확하지 않나요?"**

맞습니다. 다음 차수 과제로 냅니다. `data/reviews/{이니셜}.jsonl` 로 실제 코멘트를 쌓고
`weight_rubric` 에 회상 대신 실측 빈도를 넣는 확장입니다. 8절 참고.

**"제 문서에 써도 되나요?"**

`drafts/current.md` 로 저장하면 됩니다. `.gitignore` 에 들어 있습니다.
다만 사내 문서라면 리포를 공개 저장소에 올리지 않았는지 먼저 확인하게 하세요.

## 7. 채점 (평가가 필요한 경우)

`./scripts/check.sh` 전체 출력을 캡처해 제출받으면 됩니다. 32개 항목 중 통과 수로 갑니다.

| 통과 | 판정 |
|---|---|
| 28 이상 | 완성 |
| 22~27 | 부분 완성 — 어느 장에서 멈췄는지가 출력에 나옴 |
| 22 미만 | 미완 — 대개 3장(MCP)에서 막힘 |

8장의 자기 점검 6문항을 병행하면 "만들었다" 와 "이해했다" 를 나눠 볼 수 있습니다.

## 8. 6시간 확장 (다음 차수)

같은 뼈대로 6시간을 만들 때 **장을 늘리지 말고 깊이를 늘리세요.** 8장 구조를 유지합니다.

| 장 | 3시간 | 6시간에서 추가 |
|---|---|---|
| 1 | 문진 폼 | 문진관이 부족한 영역에 **추가 질문 3개를 그 자리에서 생성** — 에이전트가 자기 입력을 스스로 보강 |
| 2 | 규칙·계약 | 계약 위반 사례를 일부러 만들어 `save_review` 가 거부하는 걸 체험 |
| 3 | 읽기 도구 2개 | 실제 코멘트 이력(`data/reviews/*.jsonl`)을 읽는 `list_reviews` 추가. 회상 대신 실측 |
| 4 | 문진관 | 리뷰어 복수 — 파트장·팀장·본부장 체크리스트를 따로 두고 단계별로 태움 |
| 5 | 게이트 1개 | 게이트를 어디에 걸지 **수강생이 직접 정하게** 한다. 되돌리기 비용으로 토론 |
| 6 | 병렬 3인 | **A2A** — 답변관의 `missing` 을 편집관에게 되돌려 "이 데이터를 넣으면 지적이 몇 개 사라지나" 재계산. 수렴 조건 설계가 진짜 난이도 |
| 7 | 결과 화면 | 적중률 대시보드 — 차수별 예측 적중률 추이 |
| 8 | HOTL | 정지 조건을 수강생이 직접 설계하고, 일부러 걸리게 만들어 검증 |

**다른 토픽으로 옮길 때.** 바뀌는 건 셋뿐입니다.

1. 문진 12문항 (그 도메인에서 재인이 잘 되는 보기 12개)
2. `weight_rubric` 의 `CATALOG` 매핑과 점수 규칙
3. `score_draft` 의 규칙 기반 지표

하네스 여섯 요소, 게이트 위치, 병렬 구조, 화면 구성은 그대로 씁니다.
**이게 하네스를 만드는 이유이고, 6시간 차수의 첫 10분에 이 표를 보여 주세요.**
