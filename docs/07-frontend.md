# 7장 · 결과 화면 · 20분

## 이 장이 끝나면

- `state/review.json` 이 화면이 된다
- 맨 아래에 **회의 전 준비 목록** 이 나온다

---

## 실습

```
web/index.html 을 만들어줘. 의존성 없는 단일 HTML 파일이다.
state/review.json 과 (review 모드면) draft_path 의 마크다운을 fetch 해서 렌더한다.

1) 상단 요약
   - "예상 지적 N건 · 근거 있는 질문 M건 · 준비 시간 T분"
   - T가 30분을 넘으면 그 숫자를 강조한다
   - 그 아래 작게: 리뷰어 · "문진 12문항 중 A개 답변" · "확실한 항목 H개" · 모드
   - evidence.high_count 가 0이면 회색 띠로
     "확실한 근거가 없습니다. 아래 결과를 참고 수준으로 보세요"
   - halts 가 있으면 같은 자리에 표시

2) 체크리스트 패널
   - rubric 을 score 내림차순 정렬
   - high 는 굵게, medium 은 보통, low 는 40% 투명도로 흐리게
   - 항목을 클릭하면 basis(어느 문항의 어떤 답변에서 나왔는지)가 펼쳐진다

3) mode 가 "review" — 좌측 60%
   - 초안을 줄 번호 붙여 표시
   - marks 의 line 에 해당하는 줄에 왼쪽 빨간 세로선
   - 그 줄을 클릭하면 issue 와 fix 가 아래로 펼쳐진다

   mode 가 "guide" — 좌측 60%
   - guide 의 section 을 카드로. 각 카드에 must_include 를 체크박스 목록으로
   - 카드마다 근거 rubric_id 를 작게 표시

4) 우측 40% — 예상 질문 카드
   - q 를 크게, confidence 배지를 옆에
   - speculative: true 인 카드는 40% 투명도 + "근거 없음" 배지
   - answer 는 접었다 펼치는 형태
   - missing 이 있으면 빨간 점과 함께 목록으로, prep_minutes 를 옆에
   - 카드마다 복사 버튼 — "질문 / 답변 / 준비물" 이 한 덩어리로 복사된다

5) 최하단 — 회의 전 준비 목록
   - 모든 missing 을 모아 체크박스 리스트로
   - 그 아래 evidence.improve_by 를 "정확도를 올리려면: 문항 3, 7에 답해 보세요" 로

6) logs/trace.jsonl 을 1.2초마다 다시 읽어 **상단 파이프라인 + 서브에이전트 카드 + MCP 도구 + 이벤트 피드**로 표시한다.
   우측 하단 작은 타임라인만으로는 부족하다. 편집국 라이브 보드가 본체다.

7) 스타일: 무채색 + 지적 표시에만 빨강. 시스템 폰트, 1px 괘선.
   화면 폭 1400px, 좌우 분할. 그림자와 둥근 모서리 최소화.

8) review.json 이 없으면 "아직 결과가 없습니다" 를 보여준다. 에러 화면 금지.
```

```bash
./scripts/serve.sh
```

`http://localhost:8080/web/`

## 근거 없는 카드를 지우지 않는 이유

흐리게 처리된 질문 카드를 보세요. 지울 수도 있었습니다. 그런데 남겨 뒀습니다.

**근거 있는 것과 없는 것이 나란히 보이는 화면 자체가 정보입니다.**
"이건 진짜 나올 질문이고, 저건 내가 짐작한 것" 을 구분해서 회의에 들어가는 것과
전부 같은 무게로 들고 가는 것은 다릅니다.
