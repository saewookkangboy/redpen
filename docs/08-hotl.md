## HITL 과 HOTL

지금까지는 **HITL** 이었습니다. Human In The Loop.
파이프라인이 멈추고, 사람이 승인해야 다음으로 갑니다. 5장의 게이트가 그것입니다.

이제 **HOTL** 로 바꿉니다. Human On The Loop.
멈추지 않고 끝까지 돕니다. 사람은 감시만 합니다.

바꿀 곳은 두 군데뿐입니다.

---

## ① 승인 상태

```bash
echo '{ "rubric_approved": true, "mode": "HOTL" }' > state/approvals.json
```

## ② 멈출 조건

`CLAUDE.md` 맨 아래에 붙입니다.

```markdown
## HOTL 모드
mode 가 HOTL 이면 승인 요청 없이 끝까지 진행한다.
단, 아래 중 하나라도 걸리면 즉시 멈추고 사람을 호출한다.
- 필수 문항(1, 10)이 비어 있음
- high 등급 항목이 하나도 없음
- speculative: true 인 질문이 전체의 70% 를 넘음
- 저장물에 성격·성향 추정 표현이 들어감
- 저장물에 이니셜이 아닌 실명이나 회사 고유명사가 남아 있음
- 같은 에이전트 3회 실패
멈출 때는 halts 배열에 사유를 적고
logs/trace.jsonl 에 {"ev":"halt","why":"..."} 를 남긴다.
```

## 실습 · 입력을 바꿔 돌립니다

터미널을 보지 마세요. 브라우저만 봅니다.

```bash
./scripts/serve.sh
```

`intake.html` 로 돌아가 **세 가지를 바꿉니다.**

1. 빈도를 하나 올려 보세요 (2~3회 → 4회 이상). 등급이 medium 에서 high 로 올라갑니다
2. 건너뛴 문항 하나에 답해 보세요. improve_by 목록이 줄어듭니다
3. **문항 12에 초안을 붙여넣으세요.** `drafts/sample-report.md` 내용을 그대로 써도 됩니다

복사해서 Claude Code 에 붙여넣고 `/redpen`.

결과 화면이 바뀝니다. 가이드 모드였다면 검수 모드로 바뀌고, 왼쪽에 빨간줄이 그어집니다.

## 마무리 질문 세 개

**지금 여러분은 뭘 하고 있었습니까?**

감시. 이게 HOTL 입니다.

**HITL 과 HOTL 중 뭐가 더 어렵습니까?**

HOTL 입니다. 멈추는 조건을 미리 다 적어놔야 하기 때문입니다.
**자동화의 난이도는 실행이 아니라 정지 조건 설계에 있습니다.**

**"성격 추정 표현이 들어가면 멈춰라" 는 조건, 왜 넣었을까요?**

무인으로 돌기 시작하면 사람이 안 봅니다.
안 보는 상태에서 나가면 안 되는 게 뭔지를 미리 정하는 게 하네스입니다.

0장에서 그은 선이 여기서 다시 나옵니다. 수업의 처음과 끝이 같은 이야기입니다.

## 자기 점검

각 1점, 6점 만점. 4점 이상이면 완성입니다.

1. `/mcp` 에 내가 만든 서버가 뜬다
2. 체크리스트 항목에 근거 문항 번호와 신뢰등급이 전부 붙어 있다
3. 승인 없이 저장을 시도했을 때 **실제로 막혔다**
4. 초안에 빨간줄이 그어졌다 (또는 작성 가이드가 나왔다)
5. 예상 질문의 신뢰등급이 화면에서 구분된다
6. 맨 아래 준비 목록에 내가 실제로 준비할 항목이 들어 있다

보너스: 문진 답변을 고쳐 재실행했더니 결과가 달라지는 걸 확인했다.
