## 1. 완성본을 먼저 봅니다 (5분)

리포에는 예시 결과가 들어 있습니다. 먼저 띄워 보세요.

```bash
cp state/review.example.json state/review.json
cp logs/trace.example.jsonl logs/trace.jsonl
./scripts/serve.sh
```

브라우저에서 `http://localhost:8080/web/` 을 엽니다.

세 군데를 보세요.

1. **맨 위 숫자** — "준비 시간 75분". 이 회의 전에 뭘 준비해야 하는지의 총량입니다
2. **왼쪽 빨간 세로선** — 초안의 어느 줄이 왜 걸렸는지. 줄을 클릭하면 고치는 법이 나옵니다
3. **맨 아래 준비 목록** — 이게 결론입니다. 스크롤을 끝까지 내려 보세요

오른쪽 질문 카드 중 하나는 흐리게 처리돼 있습니다. **근거가 없는 질문**이라는 표시입니다.
그럴듯한 질문은 얼마든지 만들어낼 수 있기 때문에, 이 시스템은 근거 있는 것과 없는 것을 화면에서 구분합니다.

다 봤으면 지웁니다. 이제부터 이걸 직접 만듭니다.

```bash
rm state/review.json logs/trace.jsonl
```

## 3. 먼저 정하고 갑니다 (5분)

이 시스템은 **사람을 학습하지 않습니다.**

| 만드는 것 | 만들지 않는 것 |
|---|---|
| 반복 관찰된 문서 요구사항 체크리스트 | 사람의 성격·성향·심리 프로파일 |
| 항목별 근거 문항과 신뢰등급 | 답변에서 유추한 인물평 |
| 회상 빈도 | "이런 사람은 이럴 것이다" 류의 일반화 |
| 문서를 어떻게 고칠지 | 대인 전략, 설득 화법 |

> **왜 지금 이 이야기를 하나**
> 나중에 하면 늦습니다. 문진을 시작한 뒤에는 이미 머릿속에서 인물평이 만들어진 뒤입니다.
> 그리고 실용적인 이유가 더 큽니다. "숫자에 민감함"으로는 문서를 고칠 수 없지만,
> "수치 문장에 출처를 붙여라"는 오늘 당장 고칠 수 있습니다.
