# 빨간펜 (Red Pen)

문서를 보고하기 전에, **반복될 지적을 미리 잡고 회의에서 나올 질문을 준비하는** 멀티에이전트를 직접 만듭니다.

준비물은 노트북뿐입니다. 자료를 가져오지 않아도 됩니다. 12개 질문에 기억나는 만큼만 답하면 나머지는 여러분이 만든 시스템이 합니다.

```
문진 12문항  →  ① 문진관     체크리스트 + 신뢰등급
                    ◆ 승인 게이트 (사람이 확인해야 저장됨)
              →  ② 편집관   빨간줄 또는 작성 가이드  ┐
                 ③ 질문관   예상 질문                ├ 동시에
                 ④ 답변관   답변 초안 + 준비물       ┘
              →  브라우저 결과 화면
```

## 3시간 안에 무엇을 배우나

| | |
|---|---|
| **하네스 엔지니어링** | 규칙·역할·계약·관측·게이트·기억 여섯 개를 각각 파일 하나로 만듭니다 |

| **멀티에이전트** | 위원 4명이 각자 다른 권한으로, 셋은 동시에 일합니다 |
| **HITL** | 승인 없이는 저장이 **실제로 막힙니다.** 부탁이 아니라 코드가 막습니다 |
| **HOTL** | 마지막엔 손을 떼고 화면만 봅니다. 멈출 조건은 미리 적어둡니다 |

## 시작하기

```bash
git clone <이 리포 주소> redpen
cd redpen
./scripts/check.sh 0      # 환경 점검
```

문제가 있으면 [SETUP.md](SETUP.md) 를 보세요. 그다음 [docs/00-start.md](docs/00-start.md) 부터 순서대로 진행합니다.

**막히면 언제든 다음 단계 완성본을 받을 수 있습니다.**

```bash
./scripts/check.sh 3          # 3장 완료됐는지 스스로 확인
./scripts/reset.sh step-4     # 막히면 4장 시작 상태로 맞춤 (내 작업은 stash 에 백업됨)
```

## 먼저 정하고 가는 것

이 시스템은 **사람을 학습하지 않습니다.**

| 만드는 것 | 만들지 않는 것 |
|---|---|
| 반복 관찰된 문서 요구사항 체크리스트 | 사람의 성격·성향·심리 프로파일 |
| 항목별 근거 문항과 신뢰등급 | 답변에서 유추한 인물평 |
| 회상 빈도 (4회 이상 / 2~3회 / 1회) | "이런 사람은 이럴 것이다" 류의 일반화 |
| 문서를 어떻게 고칠지 | 대인 전략, 설득 화법 |

한 문장으로 말하면 이렇습니다. **우리가 학습하는 건 사람이 아니라, 그 사람이 문서에 반복해서 요구한 것입니다.**

윤리적인 이유만이 아닙니다. "김팀장은 숫자에 민감함"은 검증도 안 되고 쓸모도 없지만, "수치 문장 12건 중 9건에서 출처를 물었음 → 표 각주에 집계 기준 3종 배치"는 오늘 당장 고칠 수 있습니다.

`save_rubric` 도구가 성격 추정 표현을 **코드로 막습니다.** 규칙을 프롬프트에도 썼지만 한 번 더 막습니다. 왜 두 번 막는지는 5장에서 다룹니다.

## 개인 데이터

문진 답변과 결과는 `.gitignore` 에 들어 있어 커밋되지 않습니다. 여러분 노트북 밖으로 나가지 않습니다.

검수 대상 문서는 리포에 들어 있는 가상 보고서(`drafts/sample-report.md`)입니다. Claude Code 에서 자유롭게 고쳐가며 결과가 어떻게 달라지는지 보세요. 사내 문서를 쓰고 싶으면 `drafts/current.md` 로 저장하면 됩니다 — 이 경로도 `.gitignore` 에 있습니다.
